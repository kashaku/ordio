# Ordio 小程序

Ordio 是一个使用 uni-app、Vue 3 和 Pinia 实现的扫码点餐与门店主页搭建 MVP。顾客启动入口已经独立，商家工作台暂时仍保留在同一个开发包内。现有菜单、主页和订单业务仍使用设备本地数据，微信身份和桌码解析正在迁移到 CloudBase。

## 运行

已验证环境：Node.js 22、npm 10、微信开发者工具 `2.02.2608080`，基础库 `3.17.2`。

```powershell
npm ci
npm run dev:mp-weixin
```

微信开发者工具导入：

```text
D:\vsCode\ordio\dist\dev\mp-weixin
```

也可以在开发构建生成后执行：

```powershell
npm run devtools:open
```

这个脚本优先读取 `WECHAT_DEVTOOLS_CLI`，否则查找本机常见安装目录。使用传统 `cli.bat` 时，需要先在微信开发者工具的“设置 → 安全”中开启服务端口。

正式构建：

```powershell
npm run build:mp-weixin
```

## 顾客和商家如何进入

顾客和商家不在同一个首页选择角色。两类入口和权限来源不同：

| 使用者 | 当前入口 | 正式入口 | 权限依据 |
| --- | --- | --- | --- |
| 顾客 | 打开小程序首页后点击“扫码进入门店”，或通过桌台参数打开顾客扫码页 | 微信扫描桌台小程序码，直接进入对应门店 | 桌台令牌解析出的门店和桌台 |
| 商家 | 独立启动本仓库的响应式 Web 管理端 | 部署到独立管理域名 | 登录用户在 `store_members` 中的门店角色 |

顾客首页不会展示商家入口。客户端传入 `role=merchant`、`storeId` 等参数不能获得商家权限；商家接口必须由服务端校验门店成员关系。

### 顾客使用指南

正常使用：

1. 微信扫描商家桌牌上的小程序码，或先打开小程序再点击“扫码进入门店”。
2. 系统解析桌台令牌，确认门店和桌号后进入商家主页。
3. 查看招牌推荐，进入已发布菜单，选择规格并加入购物车。
4. 在结算页核对桌号和商品后提交订单。

当前仓库还不能生成正式可打印的小程序码。开发联调可在微信开发者工具中打开：

```text
页面：pages/customer/scan
参数：tableToken=tbl_7eJr2pkN4xQm9VaL6sTyBwUc
```

也可以使用 `scene=t=tbl_7eJr2pkN4xQm9VaL6sTyBwUc` 模拟桌台码入口。`storeId=store-demo` 仅用于旧入口兼容，只允许浏览，不作为正式堂食桌码。

桌码无效、已更新或桌台停用时，顾客会停留在入口页并看到重新扫码提示，不会跳到其他门店。

### 商家使用指南

启动独立商家管理端：

```powershell
npm run dev:merchant
```

浏览器访问：

```text
http://127.0.0.1:5174
```

开发服务器提供“进入开发预览”，便于迁移和验收主页搭建界面。该入口只在 Vite 开发模式出现，生产构建必须通过真实登录服务进入。

当前可用流程：

1. 启动管理端并进入开发预览。
2. 从经营概览进入“主页搭建”。
3. 选择模板、品牌色并编辑首屏文案，右侧实时查看顾客端效果。
4. 保存开发草稿。当前草稿只保存在浏览器，尚未发布给顾客。

菜单、桌台和员工模块正在从原小程序商家页迁移。过渡期间仍可在微信开发者工具直接打开 `pages/merchant/index` 核对旧功能，但不再把该页面作为正式商家入口或继续扩展正式功能。

上线时不会要求商家通过顾客小程序隐藏路径进入。独立管理端完成后，商家页面和写接口会从顾客构建中移除。

商家管理端生产构建：

```powershell
npm run build:merchant
```

产物位于 `dist/merchant-admin`。生产环境还需要配置 `VITE_MERCHANT_API_BASE` 并实现登录、会话、退出和门店成员权限接口；未配置时登录按钮保持不可用，不会降级为本地身份。

## 当前范围

- 商家编辑店铺、分类、菜品和规格并发布菜单
- 商家从三套模板配置品牌色、首屏文案、主页区块和招牌菜并独立发布
- 商家维护桌台令牌、启停桌台和更新旧桌码
- 顾客扫描桌码进入对应门店和桌台，再进入菜单
- 规格选择、购物车、结算和订单
- 本地付款状态和历史订单
- 本地图片与业务数据持久化

商家资料单独保存并立即对顾客端生效；主页和菜单各自维护草稿与发布副本，未发布内容不会影响顾客端。

当前只完成桌码令牌、入口解析以及 CloudBase 身份骨架，还不能生成可打印的正式微信小程序码。菜单、主页和订单尚未跨设备同步，也未接入真实支付。

CloudBase 开发环境、首批集合、索引和 `ordioApi` 已部署。本机需使用不入库的 `.env.local` 才会启用云端会话；部署状态和配置见 [docs/cloudbase-development.md](docs/cloudbase-development.md)。

当前实现和验收见 [docs/uniapp-mvp-development.md](docs/uniapp-mvp-development.md)。真实运营版的系统拆分、数据库、权限、支付、UI 和分期计划见 [docs/production-roadmap.md](docs/production-roadmap.md)。
