# 入口、桌码和主页边界

操作步骤见 [README](../README.md)，当前数据源见[开发说明](uniapp-mvp-development.md)。本文件保留参数契约和待实现边界，不重复维护部署状态。

## 现有入口契约

`entryPayloadFromOptions` 的优先级为 `scene → tableToken → storeId`，在 `pages/customer/scan` 的 `onLoad` 中处理。`parseEntryPayload` 同时接受扫码结果中的 URL 查询串或直接的令牌文本。

| 场景 | 页面 | 参数形式 |
| --- | --- | --- |
| 模拟器验证桌台入口 | `pages/customer/scan` | `tableToken=<有效令牌>` |
| 模拟 scene 入口 | `pages/customer/scan` | 查询串写 `scene=t%3D<有效令牌>`，传入的 scene 值为 `t=<有效令牌>` |
| 旧门店浏览入口 | `pages/customer/scan` | `storeId=store-demo`，只能浏览，不能确认堂食桌台 |
| 解析后的主页 | `pages/customer/storefront` | `storeId=...&tableToken=...`，由入口服务构造 |

启动页面字段不包含 `?` 和参数；启动参数字段不含开头的 `?`。`<有效令牌>` 是说明占位符，不能直接用于演示；README 给出已核对的 A01 值。

默认首页不解析上述参数。直接打开主页只适合局部页面调试，会跳过扫码入口的云端检查；完整入口验收应从扫码页开始。

## 当前链路与限制

```text
扫码页（scene / tableToken）
  → entry-service
  → 配置云环境：entry.resolveTable；未配置：本地桌台
  → 门店主页（本地发布副本和本地桌台）
  → 菜单、结算、订单（本地）
```

入口云函数校验令牌格式、桌台启用和门店 `active` 状态。不存在令牌返回 `TABLE_NOT_FOUND`；停用返回 `TABLE_DISABLED`；门店不营业返回 `STORE_UNAVAILABLE`。当前行为不是“休息门店仍展示主页”。

本地与云端桌台未同步：旧商家页更新令牌只影响本机，云端修改也不会同步到本机。云端入口成功而主页报桌码无效时，先比对两边令牌，不要重新创建门店或清空全部缓存。

## 三类码不能混用

- 预览码由开发者工具提供，供开发包手机预览；不是门店桌码生成服务。
- 桌台小程序码要绑定小程序、入口页和桌台参数；生成、云存储、下载打印尚未实现。
- 普通二维码可以编码文本供 `uni.scanCode` 读取，但编码一个 `t=...` 文本不会自动获得从微信打开本小程序的能力。

本仓库的 `buildTableScene` 只返回 `t=<令牌>` 字符串；旧商家页“复制”操作只复制该字符串，不生成图片。不要把普通二维码、预览码或复制出来的文本写成正式桌牌。

## 顾客与商家权限

顾客首页没有商家按钮。独立商家 Web 已有前端路由门禁，但正式身份服务尚未实现。旧小程序商家页仍打包且操作本地数据；目前不能声称顾客包已完全移除商家代码。

云函数中的商家动作根据微信身份和 `store_members` 检查 `owner/manager`，这不等于商家 Web 已登录，也不等于本地订单已具备服务端权限。

## 后续验收要求

正式桌码需完成生成、资源归属、下载打印、启停和令牌更新。具体微信接口、scene 长度、环境版本和账号条件必须在接入时查证，当前没有已验证的生成命令。

主页迁移后顾客只调用 `storefront.getPublished`，不存在发布版和网络失败均给出明确状态，不读取草稿或静默切回本地。未配置 CloudBase 的开发场景仍保留本地适配。

商家主页采用模板、品牌色、首屏文案和公告/招牌菜/故事/门店信息区块，保留显隐和排序；不开放任意 HTML、脚本或自由画布。云端发布还需要补并发、资源与菜品归属验证，详见[路线图](production-roadmap.md)。
